# 设计与取舍

[English](../en/design.md) | **中文**

本文说明 synapse4j 做什么、刻意不做什么，以及为什么。当你想在动手之前确认这个库合不合适，或者你
正准备改动它时，值得一读。

## 它建模并传输一次调用，但不记住这次调用

库负责构建请求、发送请求、把答案读回来。这就是它的全部工作。

它不跨调用保存任何东西。对话历史、你把它存在哪里、如何裁剪、以及把一段对话从一个提供商迁到另一个
提供商时会发生什么，全都是你应用的决策。库把数据交给你，其余不插手。

这是它与框架最主要的区别。一个替你掌管对话的框架，也同时掌管了对话如何存储、如何压缩、如何迁移
——而这些决定你可能想自己来做。这也正是这个库能保持无状态的原因：一个客户端就能服务应用里的所有
请求，不需要为每段对话各建一个实例；每次调用都显式接收它的全部输入。

一段对话靠你提供的标识符串起来。库只透传它，从不存储。

## 所有提供商共用一套模型

一次调用的大部分内容是各家都认同的：带角色的消息、模型名、温度、工具列表。共享的请求与响应类型
表达的就是这块共识。

难点在其余部分，因为各家并不认同。库用四种方式处理：

1. **它没有建模的字段会被保留，并原样发回。** 每个能携带的节点——消息、内容部分、工具——以及调用
   自己的选项，除了库认识的字段外，还能携带提供商特有的字段。提供商发来的、库叫不出名字的东西，保留
   在它来自的那个节点上，节点再次发出时原样写回，所以一次往返不会丢东西。

2. **只有当某个字段必须跨提供商保留下来、且各家对它的含义有共识时，它才进入共享模型。** 两家提供商有
   一个名字相似的字段并不够。这个字段必须确实需要跨提供商，*并且*各家的取值能映射到同一个含义。

3. **共享字段若某个协议无法表达，就不发出去，调用照常进行。** 提供商没有对应成员的设置，它就不发；
   若因此拒绝调用，换一家提供商的瞬间同一段代码就会坏掉，而这正是这个库要避免的事。唯一的例外是对答案
   形状的要求：协议无法兑现时调用失败，因为一个违反要求却看起来像成功的答案是代价最高的错误。

4. **提供商对共享字段的拼写，是该模块配置上的一个选项。** 各家端点对名字有分歧——一家要
   `max_completion_tokens`，另一家要 `max_tokens`；一家把推理内容放在 `reasoning` 下，另一家放在
   `reasoning_content` 下。这个名字是模块配置上的选项，读和写共用，默认值适合该提供商。它从不根据
   某次响应恰好含有什么来猜测，因为一段读了某个拼写却写另一个拼写的对话，会把端点从未发出过的成员
   改名。

原样通过的东西就原样通过：模块写回它读到的。把对话在提供商之间迁移，是你应用的一次刻意行为，而不是
库去猜测的事。

## JSON 库和 HTTP 客户端由你选

库自己不序列化任何值，也不自己开连接。它让一个 JSON 编解码器把值变成 JSON，让一个 HTTP 客户端发送
字节。两者在 core 里都是接口，实现放在各自的模块里。

与之相对的做法——直接依赖 Jackson 和 JDK 客户端——会让这些选择永久固定下来。在这里，你可以换掉其中
任何一个，提供商模块和你的代码都不用改。模块的拆分就源于这条规则：core 只给出接口，每个 JSON 或
HTTP 库各有一个自己的模块。

## API 长什么样，以及为什么

**阻塞，而非响应式。** 调用在答案完整后返回。异步交给 JDK——Java 21 虚拟线程——而不把库绑到
Reactor 或 RxJava 上。这样线程模型保持简单，也是库里没有任何东西把事件推给你的原因。

**流式与非流式共用同一个请求。** 请求只写一次，如何消费答案由你选。流式调用把提供商的事件按到达
顺序交给你，并组装回阻塞调用会返回的那个轮次。

**结构开放。** 用户或提供商会扩展的类型，不是 `enum`、`record` 或 `final` 类。`enum` 无法增加
取值，`record` 无法携带额外字段；两者都会阻断模型本要允许的扩展。已知会增长的取值——角色、结束原因
——是字符串加具名常量。只有规范固定了集合、没有东西会扩展它时，才使用封闭形式。

**先有需要，再做抽象。** 至少两个真实实现都用到，才值得引入一个新抽象，而不是对第三个的猜测。

**默认更省。** 在别的原则没有约束的地方，库选更省的做法——内存更少，中间步骤更少：请求边写边发，
而不是先构建成一棵树再整体序列化；响应也以同样的方式读取。

## 非目标

- 不做 agent 编排或工作流引擎。
- 不做对话记忆。历史是你的。
- 不绑定某个具体的 JSON 库、HTTP 客户端或 LLM 提供商。
